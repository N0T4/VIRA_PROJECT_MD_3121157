# Простір і взаємодія
Прийнята поведінка: D001–D008. Числові значення та точний жест — відкриті.

## Два різні типи просторових об'єктів
**World-anchored:** кімната, головний екран, місце бібліотеки.
**User-summoned:** пошук, навігація, дії, картка та локальна drop-зона.
Фіксований екран не стає панеллю, яка завжди слідує за головою.
Викликані інструменти з'являються перед користувачем; поведінку після появи перевірити окремо.
Пропозиція: вони залишаються стабільними в просторі, доки користувач не викличе recenter.

## Стан кімнати
ENTRY_LOGO → BROWSING → DETAILS → WATCHING; контролери UI мають незалежний стан visible/hidden.
WATCHING + overlay допустимий. Відкриття overlay саме по собі не означає pause.
При виході з режиму не перезапускати Activity без явної технічної необхідності.

## Розкладна Anime Card
CLOSED → OPENING → OPEN → CLOSING. Окремо: idle/focused/held/docked/hidden.
Постерна частина, секція деталей і вибір епізодів — частини одного просторового об'єкта.
Це не просто «перевернути плоску картку на 180°».
Точна кількість стулок, напрям відкриття й input-метод залишаються рішеннями DRAFT.
Пропозиція першого прототипу: дві з'єднані стулки, одна точка володіння, явна кнопка unfold плюс тест жесту.
Додавання стулки не повинно утворювати дублікати `Anime` або `LibraryEntry`.

## Перегляд і side docking
Початок відео приховує/паркує картку збоку, без втрати anime/episode state.
Recall повертає ту саму картку для episode/rating/status; не створює нову сесію плеєра.
Сторона docking залежить від комфорту/домінантної руки — ще не зафіксована.
Пауза, перемотування та вибір серії — різні команди. Зміна серії запам'ятовує позицію попередньої.
Невидимі панелі не перехоплюють input і не залишають активні колайдери.

## Drop
Grab → available target → target focus → valid release → saving → success/error.
Дані змінюються після валідного release, а «Added» — після успішного запису.
Втрата tracking скасовує намір drop. Випадкове проходження через target нічого не записує.
Кнопка й drop викликають одну бізнес-команду. Повторний Add не скидає статус/прогрес.

## Безпечні резервні дії (пропозиція)
Поки жест не перевірений, потрібен доступний summon/recenter через явний control.
Дві руки не повинні одночасно володіти grab або завершувати чужий touch.
Втрата tracking, focus loss і app pause скасовують незавершений press без фантомного tap.
Довгий текст прокручується, не рухаючи весь предмет; кнопки не перекриваються grab volumes.

## Що саме тестувати
Сидячи/стоячи; ліва/права рука; touch під час held; unfolded card біля тіла;
recenter після пересування; приховані колайдери; часткова втрата tracking; reopening; список епізодів без відеоджерела.

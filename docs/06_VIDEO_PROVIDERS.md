# Джерела відео
## Вимога власника — прийнято
Дві категорії: офіційні сервіси на кшталт Netflix/Crunchyroll та користувацькі API-підключення
до інших потрібних сервісів. Це обсяг продукту, **не доказ доступних SDK/API або дозволів**.

## Що не підтверджено
У цьому starter pack немає перевіреної інтеграції Netflix або Crunchyroll,
партнерського доступу, DRM entitlement, playback license або списку доступних catalog/video endpoints.
Логотипи в референсах — концепт. Не показувати напис «працює», доки немає capability test.

## Результат T070 — 2026-11-05

Власник підтвердив **https://animego.org/** та **https://animeua.club/**. T070 завершено як дослідження. Публічний HTML каталогів і деталей доступний; повні списки відтворюваних серій, API-контракт і внутрішнє відео VIRA не підтверджені. Robots обмежують частину маршрутів; права повторного використання перевіряються окремо. AnimeUA використовує сторонній iframe і повідомляє про територіальне обмеження. [Матриця](16_PROVIDER_CAPABILITIES.md). Інтеграцій T070 не додає.

- Netflix документує власний перегляд у Quest Browser. Вбудований плеєр чи API для VIRA цим не підтверджено.
- Сторінка Crunchyroll у Meta Store наразі позначена як анонс. Quest Browser compatibility та native/API-доступ VIRA залишаються непідтвердженими.
- Офіційний sample на зафіксованому SDK 0.15.0 демонструє DRM/direct-to-surface. Поточна VIRA поки перевірена тільки з локальним preview.
- Власне/ліцензоване HTTPS MP4 лишається можливим ізольованим тестом плеєра. Воно не замінює AnimeGO/Anime UA без рішення власника. Нових залежностей, endpoint або інтеграцій T070 не додає.

## Пропонований контракт адаптера (концептуальний, не назви SDK-класів)

Доповнення за запитом UK/EN/RU: знайдено публічні API **Mikai, Kitsu та Shikimori**, які відповіли без ключів. Запропоновані ролі — українські дані/серії, англійські та російські метадані відповідно. YummyAnime документує ru/en/uk, але потребує власного application token і має personal-use умови. Це кандидати, не новий затверджений provider. [Порівняння API](17_API_OPTIONS.md).

Власник підтвердив, що UK/EN/RU потрібні **для назв/описів і для перегляду з озвученням/субтитрами**. Тримовний каталог не закриває відеочастину. Для кожного тайтлу окремо перевіряти мову аудіо, субтитри та фактичний playback; усі три мови відео на Quest ще не підтверджені.

- Provider ID, display name, source kind, capability version.
- Auth mode / expiry / storage policy; user credentials не відправляти до стороннього proxy за замовчуванням.
- Catalog mapping, episode listing, availability, supported playback modes.
- Playback descriptor з явними типами та expiry; відсутній потік — unavailable.
- DRM capability, subtitles, seek, resume, co-watch eligibility.
- Помилки: unconfigured, auth_required, expired, unsupported, unavailable, rate_limited, offline.

## Custom API — без довільного виконання коду
Пропозиція першої архітектури: декларативна конфігурація + відомий адаптер,
а не завантаження неперевіреного Kotlin/JS та його виконання в застосунку.
Обмежувати час, розмір відповідей, redirects, дозволені схеми; не логувати bearer tokens/URL credentials.
HTTPS за замовчуванням; локальний development endpoint — окреме явне налаштування, не прихований обхід.
Секрети в platform-secure storage; у Git/меморі лише назви полів.

## Межа безпеки
Не обходити DRM, доступ або автентифікацію; не вбудовувати секрети чужих сервісів.
Користувацький провайдер повинен мати законно доступний користувачу контент.
Це інженерна межа, не юридична оцінка конкретного сервісу.

## Резервний сценарій
Рекомендація: власний/дозволений demo clip для налагодження плеєра.
Зовнішнє відкриття офіційного сервісу може бути окремою доступною capability,
але не вважається внутрішнім переглядом у VIRA й не гарантує co-watch.
За неможливості потрібної інтеграції чесно показати limitation та повернути питання власнику.

## Co-watch
Кожен учасник має окремий доступ до того самого матеріалу. Синхронізація pause/seek не надає відео.
Не обіцяти однакові таймкоди між різними монтажами/провайдерами.
